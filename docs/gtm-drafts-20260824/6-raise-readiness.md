# Raise Readiness — deck skeleton + data room DRAFT (founder-only)

*Principle: the ADP outcome is the milestone the raise hangs on. Build everything now
with that slide empty, clearly marked, so the raise starts days — not months — after the
evidence lands. Nothing here fabricates a metric; empty slots say what fills them and
which gate produces it.*

---

## 1. Deck skeleton (12 slides)

1. **The claim.** Robot pilots fail in month 3 for reasons knowable in month 0. Blueprint
   does months 0–2: capture one real workflow, rule out what can't work by measurement,
   rank what survives — before hardware ships.
2. **Why now.** Arms are cheap and multiplying; policies/candidates are multiplying
   faster; the scarce resource is *physical trial budget* at real sites. Someone has to
   decide what deserves it. (This is the wedge — deciding, not simulating.)
3. **The product.** One service: the Task Evaluation Run. Screening (measured margins,
   named causes) → ranking (gap + interval + resolution floor) → a versioned,
   digest-pinned benchmark of that site, reusable for every later candidate.
4. **The demo.** Rendered run footage: a real arm, in a real reconstructed room, executing
   a sealed task plan — with the receipts on screen. [ASSET: run video + ladder chart
   from the blog shot list.]
5. **The proof design.** The Arm Decision Proof: seal a selection between two real
   candidates *before* physical trials, then adjudicate with randomized held-out physical
   trials at the partner site. North-star metric:
   `prospectively_physically_validated_new_site_task_decisions` — currently **0 → target 1**.
   Investors should hear the number is designed to be falsifiable.
6. **THE MILESTONE SLIDE.** [EVIDENCE PENDING — filled by ADP-080 Physical Outcome Join:
   sealed decision vs physical outcome, the predicted failure boundary, and whether the
   partner changed its next physical-test allocation.] Until then this slide shows the
   gate diagram and today's position on it — honesty as design.
7. **Why it's defensible.** The evidence discipline is the moat: fail-closed gates,
   digest-bound provenance, consent/suppression/takedown enforced in the pipeline, and a
   testbed that compounds per site (re-runs are cheap; the benchmark is durable). Plus the
   two-sided network already live in product: site owners bring tasks; robot teams buy
   vetted, anonymized opportunities.
8. **How it's built.** An agent-operated engineering org: sealed paid runs supervised by
   AI agents under human authorization, ~minutes-and-cents per hypothesis at the GPU
   layer. The 79-run debugging campaign is the exhibit — velocity *with* receipts.
   [ASSET: the day's PR cadence + cost ledger.]
9. **Market path (bounded, per doctrine).** First: one proof. Then the conditional
   futures actually on the table — repeat on a second fixed-arm site-task, bounded
   capture/testbed prep, or a measured-fidelity investigation. No humanoid/marketplace
   hand-waving; the discipline is the pitch.
10. **Business model.** Per-run fee; re-runs on the existing testbed at an order of
    magnitude less (margin lives here); network access on the robot-team side. [Numbers
    from the pricing-hypothesis appendix once ≥3 prospect reactions exist.]
11. **Team + operating system.** Founder + the autonomous-org tooling; what a seed hire
    plan adds (field capture ops, partner engineering).
12. **The ask.** Sized to: N design-partner proofs + capture ops + runway to the
    reuse-decision gate (ADP-090). [Fill when raise timing is chosen.]

## 2. Data room checklist

**A differentiator to lean on: the company's operating evidence already IS a data room.**
Runs seal receipts natively; the diligence answer to "how do we know this works" is a
guided read of sealed artifacts, not a prepared PDF.

- [ ] Corporate: formation docs, cap table, IP assignments (founder + any contractor
      agents' work-product terms), trademark status for Blueprint/SiteBench naming.
- [ ] Doctrine pack (reads as governance maturity): VISION.md, north-star contract,
      evidence ladder, claim-boundary docs.
- [ ] Evidence pack: the sealed run ledger for the rehearsal campaign; spend
      reconciliation + provider-zero receipts (shows cost discipline: the entire 89-run
      controls campaign cost single-digit dollars of GPU).
- [ ] Product pack: webapp walkthrough (Task Evaluation Run preview, pilot-opportunity
      network, launch-only production API), capture-day protocol, data-handling one-pager.
- [ ] Pipeline of record: partner-conversation log from Draft 1 (the protocol answers
      double as market-validation evidence), LOIs when they exist.
- [ ] Rights & privacy: consent/takedown machinery description + a live demonstration
      script; dataset licenses for the public rehearsal scene.
- [ ] [PENDING ADP-080]: the adjudication packet — the centerpiece.

## 3. Sequencing

- **Now:** assemble everything unblocked (all boxes above except the pending one); draft
  slides 1–5, 7–11 with real content; slide 6 stays a designed placeholder.
- **At phase-5/controls completion:** refresh slide 4's demo with the passing continuous
  episode.
- **At ADP-080:** fill slide 6 and the ask; begin outreach within days.
- **Investor list:** build it now (deep-tech seed funds with robotics/sim theses +
  robotics-adjacent angels); a warm-intro map is outreach-ready material with no
