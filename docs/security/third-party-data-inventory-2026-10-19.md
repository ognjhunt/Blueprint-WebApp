# Third-party data inventory

Audit date: 2026-10-19 (America/Chicago). Source baseline: `0413fec05c16ad1ad7bfc8aa467cb6581be7ebb3`.

Scope: Blueprint-WebApp browser, API, workers, and the operations integrations implemented in this repository. This is a **source inventory for privacy review**, not a production traffic observation, executed deletion audit, or legal approval. It does not claim that every configured-optional integration is enabled, that every visitor's data reaches every provider, or that every named provider has a current contract. No credentials or live personal records were read for this inventory.

The inventory identifies **30 named service entries with implemented WebApp integration paths** below (several Google products are separate services). It also identifies **two additional infrastructure components**, **four infrastructure/development recipients supported by deployment or cross-repo contracts**, **two imported research-data sources**, and referenced-only providers. No provider's current production activity was independently verified in this audit. The free beta's core paths and conditional or historical paths are labeled separately; a source call site is not proof of live use.

Canonical copy: this Markdown file in company-controlled Git. Recovery/export: ordinary Git checkout or raw Markdown export at the recorded release SHA. Source links and line numbers below refer to the audit baseline; implementations may move during the accompanying repair. Before release, record the final commit and document digest in the release evidence. Do not rely on a chat or vendor session as the only copy.

## Imported data and configurable recipients

- **FullEnrich:** WebApp validates and imports named-person/current-role/company-domain email verification and provider-proof records produced by the Pipeline research flow. `communications-screen-contact.ts:138–156` names FullEnrich and its retained proof. This audit found no outbound FullEnrich API implementation in WebApp. It is an upstream research-data source; a complete company-wide privacy inventory must separately examine the Pipeline lookup request and provider account. Do not describe it as a browser collector.
- **Clay:** `gtmEnrichmentProviders.ts:949–1000` reads a configured local export of recipient contact/enrichment data. No Clay API call was found in that adapter. An imported historical file is not proof of ongoing vendor collection.
- **Custom search/contact discovery:** `gtmEnrichmentProviders.ts:627–658` and `cityLaunchExternalContactDiscovery.ts:141–167` support allowlisted configurable URLs. The endpoint operator can receive a company/person/contact search query or requested public URL. The actual vendor is unknown without configuration; do not invent a name or assume every allowlisted host is contacted.
- **ACP harness/OpenClaw, Paperclip, Pipeline and hosted runtime:** These are configurable transport/application boundaries, not automatically distinct third-party companies. They receive the task input, workflow context or admitted scene/policy artifacts specified by the call. Identify host/provider/operator and downstream model from current configuration (`acp-harness.ts`, `integrations/openclaw/client.ts`, `paperclip.ts`, and the `*Forwarding.ts` modules) before asserting complete recipient coverage.
- **Robot-team policy endpoints/container registries:** A site's permitted evaluation can send rendered scene observations to an invited team's policy endpoint; policy images are not the raw walkthrough. The receiving company is run-specific. Registries host team-supplied images and pulls reveal resource names/connection metadata. These counterparties are not a fixed list of app subprocessors.
- **Provider names that are not sufficient proof of integration:** RunPod, AWS and Azure appear in execution schemas; Tavily appears in spend-source configuration; Higgsfield appears in creative tooling instructions. Their presence alone does not establish an active WebApp data transfer. No direct production WebApp adapters for them were established in this audit.
- **Ordinary external links:** Source citations, LinkedIn, YouTube/Hugging Face references and example robot-company links are not automatically integrations. A click can disclose a visit to the destination; source links are distinguished from embedded scripts, API calls and uploaded artifacts here. No active browser session-replay product other than PostHog's potentially remote-configurable capability was established.

## Privacy-policy gaps and verification items

1. The existing public policy already names the major beta providers. It does not name **Z.ai, OpenRouter/the selected upstream video model provider, Luma, Jina, Parallel, Brave, Calendly or Meta's internal ad-draft path**, and does not explain imported FullEnrich/Clay research data. A review draft should distinguish conditional internal paths from routine beta processing rather than announce that all are active. If obsolete routes are deliberately retired later, remove those recipients from the live processing inventory only after verifying retirement.
2. Expand the Google Workspace description to cover actual Gmail/Drive/Sheets/Calendar payloads. Include provider-dependent Redis hosting in the operational review, and the upstream Pipeline/provider boundary for Vast and research enrichment.
3. At the source baseline, GA loads before opt-in; consent mode denying cookies does not mean no third-party network request. PostHog initializes before opt-in, and recording is not explicitly disabled. First-party analytics ingestion and experiment IDs are separate from external analytics and must also be considered when making an “optional analytics off” promise. The accompanying implementation may repair these paths; verify its final tests and a browser network trace before declaring this closed.
4. Sentry's wrapper can receive user/email/extra context and baseline initialization has no app-specific `beforeSend` URL-token scrubber. Invitation-link redaction in analytics does not establish equivalent redaction in errors, request logs or every custom event property. Check actual event payloads with synthetic data only.
5. Google Fonts loads on every document, and Photon can receive typed address and exact geolocation after user action. Neither is controlled by the analytics banner. Explain these functional recipients separately; a cookie banner is not a general provider disclosure or transfer contract.
6. The existing policy's unconditional provider-use/contract promises, residency statement, provider training restrictions, deletion timelines and retention schedule need contract/operations validation. Source cannot prove signed DPAs/SCCs, vendor subprocessors, provider training settings, retention/deletion of backups or region selection. Existing recordings' retention terms must not be extended just by publishing a new draft.
7. The legal entity, `6801 Burnet Rd, Austin, TX 78757`, and legal/privacy/support addresses exist in `client/src/data/company.ts`. Ownership, deliverability, monitoring and postal acceptance were **not** verified. Do not claim a mailbox works merely because a `mailto:` link exists.
8. A complete deletion response must account for Auth, Firestore, stored media and derived artifacts, operations mirrors, messaging providers, upstream processing copies, backups and retained legal/payment evidence. A UI acknowledgment or removal of only the Auth user does not prove end-to-end deletion. Preserve lawful holds and record retained categories/reasons without silently promising universal immediate erasure.
9. The beta has no new checkout. Refund disclosure should preserve existing historical-payment rights and identify the support route, without adding a paid offer or new non-refundable conditions. Historic Connect/settlement administration is not evidence of a new beta fee.

## Review method and limits

Read root/client/server instructions, required doctrine/architecture/deployment documents, current legal pages, package dependencies, mounted routes, browser initialization, provider adapters, environment **example variable names**, external endpoint call sites and selected payload builders. Both preferred Graphify report locations were absent, so the audit followed source call sites instead. Package installation, SDK presence, CSP domains and enum values were not treated as active transmission proof. Secret values, real account records, production environment values, paid provider APIs, external sends and live mutations were outside scope.

Before publishing a definitive current-provider statement, reconcile this inventory against the deployed commit, redacted enabled-feature/provider configuration, a synthetic browser network trace for reject/accept/withdraw choices, current approved vendor agreements and upstream Pipeline inventories. Record which integration is actually enabled, its data region, retention/deletion procedure and owner. Until then, the accurate result is a comprehensive **source-supported map with explicit unknowns**, not proof that every provider is currently processing data.

## Local repair review, October 19, 2026

A follow-up source review of the accompanying worktree changes confirmed that `analytics.ts` now checks positive analytics consent before loading Google Analytics or PostHog or sending optional first-party analytics. It rechecks consent after asynchronous work, disables PostHog autocapture/page-leave/recording/heatmaps/performance capture, and includes withdrawal cleanup. These are **local implementation observations**, not proof of deployed behavior, an independently observed production network trace, or vendor-side deletion. The source-baseline findings above remain part of the audit history.

The local changes also add a `/refunds` route with footer and beta-price-section links, prerendering and sitemap inclusion. Its refund rules restate the existing free-beta and historical-purchase terms. The privacy page links to a durable, authenticated account-and-data deletion **request** with a reference/status and an admin review queue; the implementation does not claim completed erasure and does not execute blanket deletion. The proposed privacy, terms and refund documents under `docs/legal/` are explicitly review drafts, separate from the public policy, and the public privacy revision advances from `2026-11-15.2` to `2026-11-15.3` without moving its announced effective date or altering the frozen previous version. Final test results, any subsequent monitoring sanitization changes and deployment remain the release owner's verification responsibilities.
