# Source-bound customer preparation status

This slice addresses retained preparation holds and retryable worker failures that do not reach the normal customer job status before a scene intake exists. The linked contract freezes the wire shape and ownership before integration. It preserves free customer assessment, source consent, existing access boundaries and recorded robot-result precedence. It does not turn a preview, source handoff or private AI advisory packet into a completed assessment.

The existing Pipeline intake API will read the committed local worker ledger using signed-body client admission and the server-owned capture-root mapping. Unknown, mismatched or unconfigured roots are unavailable; no caller-supplied path or broader client scope is admitted. Capture birth proves source provenance; current owner, rights, selected marker/video and task context require fresh checks. The reader verifies the ledger revision around that source/context check. Existing nonce/rate/lease admission bookkeeping remains; status reads do not mutate capture state or dispatch providers.

A callback only requests reconciliation. The WebApp rereads the current canonical status and fences its exact source and context before persisting a preparation subtree and pending notification intent. Customer polls and notification dispatch also check canonical current state. Callback order alone cannot establish the latest attempt. Delivery retries stay separate from processing retries, run outside the producer lease lock, and preserve committed failure evidence if transport fails.

The public status uses a host-derived correlation reference and safe next steps. Raw paths, exceptions, provider payloads, credentials and footage stay private. Pending notification intent uses the existing durable outbox, deduplicated by source/context/milestone; tests use local sinks only.
