# Reconstruction belongs to Blueprint

After a site uploads, Blueprint handles reconstruction and evaluation. Atlas
searches existing video frames, reuses retained work and performs bounded scene
completion. Advisory missing-view findings remain internal context rather than
a required upload or brief-confirmation step. The website only reports ready
work when the corresponding retained reconstruction or result exists.

The saved-job page keeps corrections and extra video in collapsed optional
details. Historical coverage from another recording cannot become the selected
recording's next action. Current failures, consent withdrawal and real result
limitations remain visible without inventing progress or physical success.

If the owner chooses to add another angle, `append_views` issues a same-job link
with `recording_scope: additional_views`. The old `additional_views` request
keeps its complete-walkthrough meaning. Complete-only histories continue using
v1. V2 binds the ordered active recordings, stops at the latest replacement,
and preserves every original and historical source link.

The paired Pipeline consumer verifies those originals and supplies one derived
method video to the existing Atlas/preparation path. The shared fixture is
`server/tests/fixtures/website-additional-views-vector.json`. An extra clip is
not analyzed again as a complete new job by WebApp's optional coverage/advisory
workers, and cannot overwrite the original brief or reset paid attempts. A
later complete replacement remains eligible for the existing full-video review.

Atlas grants pin the complete active source set and method digest. Existing
private ownership, recording permission, source identity, provider terms,
spending history and caps remain authoritative. There is one evaluation path.

Release order is consumer first. Core simplification does not need to wait for
optional extra recordings. Retain the coordinated release/deployment owner and
founder holds. Local/hosted tests are source evidence; completion still requires
the exact deployed pair and a real supported upload through a scored result,
return visit and recovery.

Validation: 447 focused tests passed across the saved-job page, status API and
workspace, notifications, actual two-recording upload routes, source bindings,
grants, coverage/advisory queues and source previews. TypeScript and Graphify
passed; the shared fixture matches Pipeline byte for byte. No live upload,
provider/model call, new account, spending or deployment was performed.
