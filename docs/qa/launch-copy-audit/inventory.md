# Launch copy audit: screen inventory

Visual record and extracted visible text of every customer screen we could render, captured 2026-11-20.
Auditors judge the copy; this file only lists what a customer sees and where it comes from.

- **Screens:** `screens/<slug>__<persona>__<1280|390>.jpg`. Full page, JPEG quality 60, device scale factor 1. Desktop is 1280 × 900. Phone is 390 × 844 with touch and an iPhone user agent, so phone-only branches render (for example, the recorder instead of the QR code). 95 screens, 190 images, about 14 MB.
- **Text:** `text/<slug>__<persona>.txt` holds three parts:
  - `document.body.innerText` at 1280.
  - A section with the lines that only appear once every `<details>` is opened and every tab is clicked: collapsed help, "What you're agreeing to", the sample-job tabs and so on.
  - The phone text, when it differs from desktop.

## How it was captured

- **Signed-out site, port 4410.** Started with `. ~/.blueprint-cloud/env.sh` and the playwright.config.ts web-server prefix: `BLUEPRINT_E2E=1 BLUEPRINT_DISABLE_OPS_AUTOMATION_SCHEDULER=1 FIREBASE_SERVICE_ACCOUNT_JSON= GOOGLE_APPLICATION_CREDENTIALS= PORT=4410 npx tsx server/index.ts`. Without `NODE_ENV=production` this server serves the client through Vite middleware, which is dev mode.
  - It was restarted with placeholder `VITE_FIREBASE_*` client values: an API key, auth domain, project, bucket, sender and app id that point at no real project.
  - Without them, `client/src/lib/firebase.ts` throws. `/sign-in` then shows "Google sign-in is unavailable. Please sign in with email and password." and `/claim/*` renders blank. Neither happens in production, which has the config.
  - Every Firebase-dependent screen was recaptured after the restart.
- **Signed-in personas, port 4411.** Same prefix plus `VITE_BLUEPRINT_OPERATOR_QA_FAKE_AUTH=1` (`client/src/lib/operatorQaAuth.ts`, dev only). The signed-in user is always the fake admin `operator-qa@tryblueprint.local` ("Operator QA", roles admin and ops).
  - The site and company personas set `localStorage.blueprint_workspace_qa_role` to `site_operator` or `robot_team`. Staff leave it unset.
  - What a company or site sees is set by the mocked server answers, for example `access.staff=false` and `status: "approved"`.
  - So wherever a page prints the viewer's email, it prints the fake admin's address. The real customer's address would appear in the same place.
  - No customer page we captured branched on the client-side admin claim. The staff note on the job library comes from the server's `access.staff`.
- **Browser.** Chromium through the `playwright` 1.57 library, scripted from the session scratchpad. No repository file other than this folder was written.
  - Every request to a host other than 127.0.0.1 was answered empty (fonts, analytics, maps).
  - Cookie consent was pre-seeded as "necessary only" for every screen except `cookie-banner`.
  - The camera was blocked (`getUserMedia` throws), so no recording state was captured.
  - `legal-update-banner` ran with the browser clock set to 2026-11-18, because the 2026-11-19.1 update has already taken effect today and the banner no longer shows.
