# Findings

First-principles audit of Blueprint-WebApp and BlueprintCapturePipeline, 2026-11-22.
One row per finding. The same rows, with every field, are in `findings.json`.

**140 findings: 3 P0, 46 P1, 91 P2.** They began as 190 candidates from
twelve agents (two inventories, five journeys, five dimension hunts) and were
merged to 139. One more was found during checking.

**How they were checked.** Every P0 and P1 (80 findings) went to a second
agent whose job was to refute it: open each cited line, rerun the cited
command, check production (the live site and the Pipeline's running release,
not only the code at head), test whether the proposed change would break
privacy, rights or money, and look for the "missing" thing under another
name. Result: 21 confirmed, 58 corrected, 1 left unverified, none refuted.
Most corrections lowered the severity: the first pass had 12 P0. The 59 P2
findings were not checked a second time; the last column says so.

**Reading a row.** The id's prefix names where it came from: A to E are the
journeys (site, deployment company, Pipeline, owner, investor walkthrough);
G gates, M missing against doctrine, F fragile, O observability and billable
events, V vestigial; IW and IP the two inventories; L1-N1 was found during
checking. "(also …)" lists the same defect reported by other agents. Evidence
paths start with `webapp:` or `pipeline:`. "door-ro" means a read-only
command of the Pipeline's operator door. The full text, every check the
second agent ran and every correction are in `findings.json`.

**Production.** The live site ran the audited WebApp commit (`0ee5df6`). The
Pipeline's control plane ran release `cbff06b`, a few commits behind the
audited head (`7d8b532`).
